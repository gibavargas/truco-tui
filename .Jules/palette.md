## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.
## 2026-06-12 - Added ARIA Labels to Chat Inputs and Removed Redundant Aria-Labels

**Learning:** When using standard `make` processes for TS/Web-bundling that do not have explicitly defined frontend linters inside `package.json`, do not run tools like `npm run lint` or `npm run format`. Doing so fails because the package lacks these scripts. The frontend verification should be done directly via `make browser`. Additionally, adding `aria-label` tags where native `<label for>` elements are sufficient creates redundant metadata and could clutter screen-reader experiences.

**Action:** Rely on `make browser` and `go test` for verification in codebases without explicit npm `lint/format` scripts. Also, prioritize fixing `<input>`s that lack labels (like placeholder-only chat inputs) but avoid over-annotating elements like `<select>` that already have connected `<label for>` attributes.

## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.
## 2025-03-11 - Chat input ARIA labels and HTML5 Form Validation
**Learning:** Text inputs without an explicit visible `<label>` (such as compact chat inputs relying only on placeholders) fail accessibility checks because screen readers cannot accurately announce the field's purpose. Additionally, adding native HTML5 `required` attributes to necessary inputs like names, invite keys, and chat inputs prevents empty submissions without requiring custom JS validation logic.
**Action:** Always include an `aria-label` attribute on inputs that lack a visible `<label>`. Default to using native HTML5 form validation attributes (`required`, `type="email"`, etc.) before writing custom JS validation logic to ensure robust, accessible, and zero-dependency client-side validation.

## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.

## 2025-03-11 - Chat Input Accessibility and Form Validation
**Learning:** Text inputs without an explicit visible `<label>` (like compact chat inputs relying only on placeholders) must include an `aria-label` attribute to ensure screen readers can accurately announce the field's purpose. Furthermore, defaulting to native HTML5 form validation (`required`) before writing custom JavaScript validation logic provides robust, accessible, and zero-dependency client-side validation for simple required text inputs.
**Action:** Add `aria-label` matching the placeholder for inputs lacking explicit labels. Add `required` to any text inputs where an empty string is an invalid submission, avoiding custom validation unless necessary.

## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.
## 2024-05-18 - Chat Input Accessibility and Validation
**Learning:** Compact form fields (like chat boxes) that rely solely on `placeholder` text for visible labeling are inaccessible to many screen readers. Furthermore, submitting empty chat messages or names is a poor UX pattern that fails backend validation but provides no client-side feedback.
**Action:** Always add an explicit `aria-label` to text inputs lacking visible `<label>` elements. Use native HTML5 form validation (`required`) for simple fields like names and chat messages before writing custom JS validation logic, as it provides a robust, accessible, zero-dependency client-side validation that integrates natively with existing form submission handlers.

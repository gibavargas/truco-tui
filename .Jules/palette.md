## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.
## 2026-06-11 - Compact Form Inputs Accessibility
**Learning:** Text inputs that rely solely on `placeholder` attributes for context (like compact chat inputs within a small form layout) are not always reliably announced by screen readers. While visual users can infer the purpose from the placeholder and adjacent submit button, non-visual users may just hear "text input".
**Action:** When an explicit visible `<label>` wrapper isn't structurally feasible (e.g. for tight spatial layouts), always provide an `aria-label` attribute on the input field containing a concise, translated string (e.g. `aria-label="${escapeHtml(t('lobby_chat'))}"`) to guarantee screen readers announce its specific purpose.

## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.

## 2024-06-19 - Form Accessibility and Native Validation
**Learning:** For compact UI components where visual labels are omitted to save space (like in-game chat inputs), screen readers are left without context if relying solely on placeholders. Furthermore, native HTML5 validation (`required`) is a powerful, zero-dependency method for preventing empty submissions on simple text inputs, but requires clear implicit or explicit label associations to be fully accessible.
**Action:** Always provide explicit label bindings via `id` and `for` attributes on standard form fields. For compact fields lacking a visual `<label>`, always add a descriptive `aria-label`. Use the HTML5 `required` attribute for simple mandatory fields (like name or chat messages) to leverage built-in browser validation and accessibility features.

## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.

## 2025-03-12 - Form Accessibility & Validation
**Learning:** Implicit label nesting (`<label><span>Name</span><input></label>`) is sometimes insufficient for strict screen reader contexts. Also, compact UI inputs that rely purely on placeholders (like chat bars) lack context for assistive tech. Finally, client-side validation for critical fields shouldn't solely rely on JavaScript if HTML5 `required` can prevent empty submissions gracefully.
**Action:** Use explicit bindings (`for="id"` and `id="id"`) for forms. Add `aria-label` to inputs that don't have visible accompanying text labels. Use native HTML attributes like `required` to prevent empty submissions on critical fields before writing custom JS logic.

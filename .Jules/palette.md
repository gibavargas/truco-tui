## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.

## 2025-05-27 - Form Input Accessibility & Native Validation
**Learning:** Compact chat inputs often rely on a `placeholder` to describe their purpose instead of an explicit visible `<label>`, making them completely inaccessible to screen readers that ignore placeholders. Moreover, manually validating trivial string inputs (like a player name or an invite key) in JavaScript is redundant when modern native HTML validation (`required`, `type`, `pattern`) handles checking seamlessly with built-in, translated error tooltips.
**Action:** When working on inputs without a visible wrapper `<label>`, immediately add an `aria-label` attribute describing the input. Further, always lean on native HTML5 constraint validation (`required`) over implementing custom JS checks for simple fields to optimize performance and reduce code complexity.

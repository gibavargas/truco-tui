## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.

## 2023-10-26 - Applying Accessibility to Cards Used in Game Screen
**Learning:** Adding `aria-hidden="true"` to card captions without simultaneously ensuring that the corresponding visually rendered card elements inherently have an `aria-label` or role will cause regressions. When dealing with functions receiving dependencies explicitly like `renderCard(card)`, ensure all callers or definitions of `renderCard` (whether centralized or local) include the accessibility labels correctly to not leave users with invisible captions and no fallback text.
**Action:** Always verify `renderCard` accessibility implementation matches the hidden states across different files where it is exported/used.

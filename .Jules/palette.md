## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.

## 2025-05-30 - Compact Form Inputs Accessibility
**Learning:** Text inputs without an explicit visible `<label>` (e.g., compact chat inputs relying only on placeholders) lack context for screen reader users, making it difficult for them to know what information to enter. Furthermore, failing to use standard HTML5 form validation (like the `required` attribute) misses an opportunity for accessible and robust client-side validation that requires no extra JS.
**Action:** Always include an `aria-label` attribute on inputs that don't have a visible `<label>`, ensuring screen readers announce the field's purpose. Add the `required` attribute to mandatory inputs to utilize native HTML5 validation before writing custom JS logic.

## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.
## 2025-03-11 - Form Accessibility and Validation
**Learning:** Text inputs that rely solely on `placeholder` attributes (like compact chat inputs) are inaccessible to screen readers once the user starts typing, as the placeholder disappears. Additionally, simple required fields (like names and chat messages) often lack client-side validation, leading to silent failures or unnecessary server roundtrips on empty submissions.
**Action:** Always provide an explicit `<label>` or an `aria-label` for every input field. Default to using native HTML5 form validation attributes like `required` on mandatory fields to provide robust, zero-dependency client-side validation feedback before writing custom JavaScript validation.

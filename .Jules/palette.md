## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.

## 2026-05-16 - Form Accessibility and Validation
**Learning:** Text inputs without an explicit visible `<label>` (such as compact chat inputs that rely solely on `placeholder` text) need an `aria-label` attribute to ensure screen readers can accurately announce the field's purpose. Additionally, default to using native HTML5 form validation (like the `required` attribute) before writing custom JavaScript validation logic for simple fields. It provides robust, accessible client-side validation that works seamlessly with existing form submission handlers and prevents empty states natively.
**Action:** Always add `aria-label` to placeholder-only inputs and apply native HTML validation attributes like `required` to mandatory form fields to enhance both UX and accessibility without relying on complex JS validation.

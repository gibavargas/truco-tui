## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.

## 2023-10-27 - Form Input Validation and Accessibility
**Learning:** For small/compact input fields like "chat messages" that rely only on a visual `placeholder` and lack a visible `<label>`, screen readers may fail to announce the field's purpose properly. Additionally, relying on backend-only validation for basic empty-field checks leads to unnecessary network roundtrips and a poor user experience. Native HTML5 form validation (`required`, `type="url"`) works effectively within this specific preact/vanilla TS app.
**Action:** Always add an `aria-label` matching the `placeholder` to visually label-less inputs. Prioritize native HTML5 `required` and specific input types (e.g., `type="url"`) to provide immediate, accessible client-side validation before implementing custom JS validation.

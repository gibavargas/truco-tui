## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.

## 2024-05-18 - Improve form accessibility and validation
**Learning:** Native HTML5 validation (`required`) provides a robust, accessible, and zero-dependency client-side validation that seamlessly integrates with existing form submission handlers. Text inputs without an explicit visible `<label>` (like compact chat inputs relying only on placeholders) must include an `aria-label` attribute to ensure screen readers can accurately announce the field's purpose.
**Action:** Always use native HTML5 form validation (`required`, `type="email"`, `pattern`) before writing custom JavaScript validation logic for simple fields. Ensure all text inputs without visible `<label>` tags have an `aria-label` attribute.

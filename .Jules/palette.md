## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.

## 2024-06-24 - Enhance Form Validation and Accessibility
**Learning:** For compact chat interfaces where labels are visually hidden and placeholders are used, `aria-label` attributes are crucial for screen reader accessibility. Furthermore, utilizing native HTML5 `required` validation on critical inputs (like names, invite keys, and chat messages) prevents empty submissions and provides zero-dependency, robust client-side validation that seamlessly integrates with generic form handlers.
**Action:** When implementing or refactoring form inputs, especially those without visible labels or those necessary for basic operation (like chat), always include appropriate `aria-label` and `required` attributes before considering custom JS validation logic.

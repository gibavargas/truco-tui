## 2025-03-11 - Playing Card Accessibility\n**Learning:** When rendering custom CSS-based playing cards that use repeated characters and decorative unicode symbols for the suit, screen readers will read out confusing, nonsensical strings like '4 ♦ ♦ 4 ♦'. To fix this, mark the entire card container with `role="img"` and an `aria-label` containing the readable label (e.g. '4 de Ouros'), while setting `aria-hidden="true"` on all the child elements containing the visual symbols and duplicating caption texts. \n**Action:** Use this `role="img"` with `aria-label` pattern anytime visual text/unicode combinations act purely as decorative graphical elements rather than meaningful flowing text.

## 2025-03-11 - Compact Form Input Accessibility
**Learning:** Text inputs that rely solely on a visual `placeholder` (like compact chat inputs) are often inaccessible to screen readers because they lack an explicit `<label>`. While visible labels are preferred, in space-constrained designs where this isn't possible, an `aria-label` must be provided. In localized TS apps, using `aria-label="${escapeHtml(t('key'))}"` (with single quotes for the translation key) successfully injects the localized label without breaking string interpolation.
**Action:** Always add an `aria-label` attribute to any form input that lacks an explicit `<label>` element, especially in compact designs, and ensure template literals use proper quoting to prevent syntax errors.

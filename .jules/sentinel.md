## 2024-04-14 - Predictable Fallbacks in Cryptographic Entropy Sources
**Vulnerability:** Several functions (`newRelayServer` and `randomHex` in `cmd/truco-relay/main.go`, and `randomKey` in `browser-edition/cmd/httpapi/main.go`) used predictable fallback values (hardcoded strings or timestamps) if `crypto/rand` failed to generate entropy.
**Learning:** Falling back to predictable values when entropy generation fails compromises the security of cryptographic operations, session keys, and secrets. It creates a silent failure where the system appears to work but is fundamentally insecure.
**Prevention:** If an entropy source fails during cryptographic operations or secret generation, the application must panic and fail-closed rather than continuing with insecure fallback values.
## 2024-05-18 - Missing Temporal Validation on Custom TLS Verification
**Vulnerability:** When `InsecureSkipVerify: true` is used along with `VerifyPeerCertificate` to manually pin TLS fingerprints, standard TLS expiration checks (`NotBefore` and `NotAfter`) are bypassed.
**Learning:** `VerifyPeerCertificate` only provides raw bytes and forces developers to skip default validation, easily leading to missed expiration checks. This allows attackers to potentially reuse old, compromised certificates if they match the fingerprint.
**Prevention:** Use `VerifyConnection` (available in Go 1.15+) instead of `VerifyPeerCertificate`. `VerifyConnection` provides parsed `x509.Certificate` objects, making it easier to manually validate expiration (`now.Before(cert.NotBefore) || now.After(cert.NotAfter)`) alongside custom checks like SHA-256 fingerprint matching.

## 2024-04-14 - Predictable Fallbacks in Cryptographic Entropy Sources
**Vulnerability:** Several functions (`newRelayServer` and `randomHex` in `cmd/truco-relay/main.go`, and `randomKey` in `browser-edition/cmd/httpapi/main.go`) used predictable fallback values (hardcoded strings or timestamps) if `crypto/rand` failed to generate entropy.
**Learning:** Falling back to predictable values when entropy generation fails compromises the security of cryptographic operations, session keys, and secrets. It creates a silent failure where the system appears to work but is fundamentally insecure.
**Prevention:** If an entropy source fails during cryptographic operations or secret generation, the application must panic and fail-closed rather than continuing with insecure fallback values.
## 2024-04-14 - Timing Attacks in Token Comparison
**Vulnerability:** The application used the standard string equality operator (`!=`) to compare sensitive authentication tokens (`HostAdminToken`) in `cmd/truco-relay/main.go`. This makes the application vulnerable to timing attacks, where an attacker can guess the token character by character by measuring the response time (since standard string comparison fails fast on the first mismatched character).
**Learning:** Comparing sensitive strings or tokens with standard equality operators introduces subtle but critical vulnerabilities. Even within the same language context, standard string equality is never safe for cryptographic or authentication-critical paths.
**Prevention:** Always use `crypto/subtle.ConstantTimeCompare([]byte(a), []byte(b)) == 1` (or `!= 1` for inequality) when comparing sensitive tokens, secrets, or passwords to ensure constant-time execution and prevent timing side-channels.

## 2024-04-14 - Predictable Fallbacks in Cryptographic Entropy Sources
**Vulnerability:** Several functions (`newRelayServer` and `randomHex` in `cmd/truco-relay/main.go`, and `randomKey` in `browser-edition/cmd/httpapi/main.go`) used predictable fallback values (hardcoded strings or timestamps) if `crypto/rand` failed to generate entropy.
**Learning:** Falling back to predictable values when entropy generation fails compromises the security of cryptographic operations, session keys, and secrets. It creates a silent failure where the system appears to work but is fundamentally insecure.
**Prevention:** If an entropy source fails during cryptographic operations or secret generation, the application must panic and fail-closed rather than continuing with insecure fallback values.
## 2026-07-08 - Validate Certificate Expiration in P2P Pinning
**Vulnerability:** The P2P TLS transport ignored certificate expiration dates when validating pinned certificates because it used `VerifyPeerCertificate` alongside `InsecureSkipVerify: true`, which disables standard expiration checks, and the custom function only verified the SHA-256 fingerprint.
**Learning:** While fingerprint pinning provides strong cryptographic assurance of identity, failing to check `NotBefore` and `NotAfter` allows stale or compromised certificates to remain valid indefinitely in the application's view, breaking the principle of least privilege for credential lifespans.
**Prevention:** Always use `VerifyConnection` (preferred in Go 1.15+) over `VerifyPeerCertificate` when implementing custom TLS validation with `InsecureSkipVerify: true`, and explicitly validate the certificate's validity bounds (`NotBefore` and `NotAfter`) against `time.Now()` alongside any custom fingerprinting.

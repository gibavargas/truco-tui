## 2024-04-14 - Predictable Fallbacks in Cryptographic Entropy Sources
**Vulnerability:** Several functions (`newRelayServer` and `randomHex` in `cmd/truco-relay/main.go`, and `randomKey` in `browser-edition/cmd/httpapi/main.go`) used predictable fallback values (hardcoded strings or timestamps) if `crypto/rand` failed to generate entropy.
**Learning:** Falling back to predictable values when entropy generation fails compromises the security of cryptographic operations, session keys, and secrets. It creates a silent failure where the system appears to work but is fundamentally insecure.
**Prevention:** If an entropy source fails during cryptographic operations or secret generation, the application must panic and fail-closed rather than continuing with insecure fallback values.
## 2024-05-19 - Insecure TLS Validation Missing Expiration Check
**Vulnerability:** A custom TLS configuration used `InsecureSkipVerify: true` and `VerifyPeerCertificate` to only check the SHA-256 fingerprint, completely ignoring standard validation rules like `NotBefore` and `NotAfter` expiration limits.
**Learning:** Overriding TLS verification with `InsecureSkipVerify: true` disables *all* Go standard library certificate checks, meaning the developer assumes full responsibility for implementing certificate expiration, revocation, and hostname checks manually.
**Prevention:** In Go 1.15+, always use `VerifyConnection` instead of `VerifyPeerCertificate` when skipping standard verification, as it provides access to the full `ConnectionState` (including the actual peer certificate) allowing explicit checks on `cert.NotBefore` and `cert.NotAfter`.

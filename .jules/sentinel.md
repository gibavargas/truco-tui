## 2024-04-14 - Predictable Fallbacks in Cryptographic Entropy Sources
**Vulnerability:** Several functions (`newRelayServer` and `randomHex` in `cmd/truco-relay/main.go`, and `randomKey` in `browser-edition/cmd/httpapi/main.go`) used predictable fallback values (hardcoded strings or timestamps) if `crypto/rand` failed to generate entropy.
**Learning:** Falling back to predictable values when entropy generation fails compromises the security of cryptographic operations, session keys, and secrets. It creates a silent failure where the system appears to work but is fundamentally insecure.
**Prevention:** If an entropy source fails during cryptographic operations or secret generation, the application must panic and fail-closed rather than continuing with insecure fallback values.
## 2026-06-21 - [CRITICAL] TLS Verification and Entropy Source Security
**Vulnerability:** The P2P TLS transport was missing validation for certificate expiration (`NotBefore`/`NotAfter`) and was checking fingerprints insecurely when using `InsecureSkipVerify: true`. It used the `VerifyPeerCertificate` callback which does not check dates. Additionally, standard string comparison (`==`) was used for certificate fingerprints, leaving the system susceptible to timing attacks. Finally, failing entropy operations (`rand.Read`) during token and key generation were returning empty values instead of panicking.
**Learning:** Using `InsecureSkipVerify: true` overrides default TLS verification, but applications still need to check valid temporal parameters when manually verifying pinned certificates. Time comparison timing attacks can occur if `ConstantTimeCompare` isn't used for security checksums. Failing closed on entropy loss prevents silent fallback to predictable, exploitable key states.
**Prevention:** Use `VerifyConnection` instead of `VerifyPeerCertificate` to get full TLS connection context to validate both fingerprints and the certificate timestamp (`NotBefore`/`NotAfter`). Always use `crypto/subtle.ConstantTimeCompare` for string comparisons of tokens or hashes. Finally, explicitly panic (`panic("entropy source failed")`) whenever a cryptographic PRNG operation fails.
